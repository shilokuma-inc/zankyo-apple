# BeatSaver の譜面をユーザーが取り込む導線の検討

- 調査日: 2026-10-08
- 前提: BeatSaver の曲・譜面はアプリに同梱しない。ユーザーが自分で取り込むための導線だけを置く
- 関連: [Discussion #4 音源・譜面の利用条件の整理](https://github.com/shilokuma-inc/zankyo-apple/discussions/4)

> [!NOTE]
> 公開情報をもとにした整理で、法的な助言ではない。

## 結論

導線の作り方でリスクが大きく変わる。

- **BeatSaver のサイトを Safari で開くリンクと、取り込み方の説明までにとどめるなら、十分現実的**
- アプリが譜面を取得する導線（キーや URL の入力、独自 URL スキーム、アプリ内ブラウザ）は、同梱しないとしても避けたほうがよい

## 導線のパターン別の評価

| 導線 | App Store 審査 | 法的リスク | 評価 |
| --- | --- | --- | --- |
| ① ヘルプに取り込み手順だけを書く（入手先は書かない） | 低 | 低 | ◎ 最も安全 |
| ② ①に加えて、BeatSaver のトップページを Safari で開くリンクを置く | 低〜中 | 低 | ○ おすすめ |
| ③ 「このAppで開く」・共有シートで zip を受け取れるようにする | 低 | 低 | ○ ①②と組み合わせる |
| ④ 譜面のキーや URL を入力すると、アプリが API でダウンロードする | 中〜高（5.2.3） | 中 | △ BeatSaver からの許可が前提 |
| ⑤ `beatsaver://` などの URL スキームで、ワンクリックで取り込む | 中〜高（5.2.3） | 中 | △ BeatSaver 公式のふりと受け取られかねない |
| ⑥ アプリ内ブラウザで BeatSaver を表示し、ダウンロードを受け取る | 高（5.2.2 / 5.2.3 / 1.2） | 中〜高 | ✕ |

審査の列の番号は [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) の項目。

## 分かれ目は「ダウンロードしているのは誰か」

**①〜③ はユーザーが自分でダウンロードしている。**

- ユーザーは Safari で BeatSaver を開き、自分で zip を保存して、アプリに渡す。アプリはファイルを読むだけなので、VLC のような汎用プレイヤーと同じ立場になる
- トップページへのリンクを 1 つ置く程度なら、リーチアプリ規制（著作権法 113条2項）の対象には当たりにくいと考えられる。対象は「殊更に誘導」するもの、または「主として侵害著作物等の利用のために用いられる」ものとされ、侵害コンテンツへのリンクを中心に提供するアプリを想定している

**④〜⑥ はアプリが取得している。**

- 審査ガイドライン 5.2.3 の「外部サービスからメディアをダウンロードする機能」に当たり、BeatSaver からの明示的な許可を求められる
- BeatSaver が許可しても、楽曲の権利までは許諾できない。それを理由にリジェクトされる余地が残る

## ②③で作る場合の注意点

1. **リンク先はトップページだけにする**: 特定の市販曲の譜面や、人気曲の一覧にはリンクしない
2. **誘導の言葉を控えめにする**: 「人気曲が遊べる！」ではなく、「お手持ちの譜面ファイル（Beat Saber 形式の zip）を取り込めます」程度にする
3. **注意書きを添える**: リンクの近くに「権利を確認できる譜面だけを取り込んでください。BeatSaver は第三者のサイトで、本アプリとは無関係です」と書く
4. **リンクは外部の Safari で開く**: アプリ内のブラウザ（`SFSafariViewController` や `WKWebView`）は使わない
5. **審査メモには正直に書く**: 「外部サイトへのリンクを置いているだけで、アプリ自体はダウンロードしない。ユーザーが持っているファイルを取り込む」と説明し、自作曲のサンプル譜面で動作を確かめられるようにする。リンクの存在を隠すと、隠し機能とみなされる別のリスクになる
6. **App Store の説明文やスクリーンショットでは BeatSaver を前面に出さない**: 書くとしても「Beat Saber 形式の譜面ファイルに対応（非公式）」くらいにとどめる

## さらに安心にするなら

- BeatSaver の運営に、Discord などで「こういうアプリでトップページにリンクを置きたい」と一声かけておく。規約上は必須ではないが、審査で権利の根拠を聞かれたときの材料になり、コミュニティとの関係も良くなる
- 審査で BeatSaver への言及を指摘されたら、①（入手先を書かない）に下げれば対応できる。最初からリンクのオン・オフを切り替えやすい作りにしておく

## Discussion #4 の案との対応

- 案 A（アプリ内検索とダウンロードをそのまま公開する）は、④〜⑥ と同じく「アプリが取得する」側に入る
- 案 B（ユーザーが用意した ZIP の読み込みだけにする）は、①〜③ に当たる
